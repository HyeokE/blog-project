# When We Meet — New meeting dialog (UI-only handoff)

2026-09-30. Implement after the four-tab/Invite people/Sonner phase. This specifies presentation and client interaction only; no application code, server API, database, OAuth configuration, dependencies, or saved room data changed here. Companion: `../craft-when-we-meet-ui-handoff.md` and `../craft-design-system.md`.

## Baseline and ownership

`src/features/when-we-meet/WhenWeMeet.tsx` currently renders the signed-in owned list plus an inline form when `showCreate` is true; `New meeting` merely sets that boolean. Guest entry currently shows the form inline, `create()` validates via `validateRoom`, saves a session draft and opens a custom login prompt if signed out; successful creation gives a Sonner toast and invitation link. `DateRangePicker.tsx`, `DateTimePicker.tsx`, `draft.mjs`, and `when-we-meet.css` already own selection, draft and style behavior. Adapt rather than duplicate those domain controls. Keep the existing saved room untouched. Current authenticated desktop phase has four English room tabs and a header Invite people action; neither is a target for redesign in this slice. The existing login prompt uses a manually implemented `role=dialog`; avoid two simultaneously mounted focus traps.

## Entry and hierarchy

- Signed-in home stays list-first. `New meeting` beside the heading opens a shared shadcn/Radix `Dialog`; the list stays mounted behind its overlay. No inline second form or page navigation. Empty-list creation uses the same handler.
- Guest home retains a discoverable, accessible `Create a room` entry/CTA and returning-user `Already have an account? Sign in with Google`. The guest can open and complete the *same* dialog before being asked to sign in. Do not auto-open OAuth or block entry with a login banner. Do not leave a second copy of the long form below the home heading.
- Dialog title `New meeting`; one short description, `Choose the dates and times, then create your room.` Form order: `What are we planning?` (free-text title, max 100), `Dates · up to 14 days`, `From`, `To`, `Room timezone`, `Your name` (free text, max 50). No promotional hero, nested cards or invented metric. Keep title/name as plain inputs; date/time are site-styled selection widgets, not exposed native pickers. Time options are direct half-hour choices with existing 09:00–18:00 defaults and end later than start. A searchable timezone chooser is desirable **only if** its option source supports a real valid IANA list; until then keep current editable timezone and validate it rather than fabricating suggestions or adding a dependency.
- Fixed footer within the dialog: secondary `Cancel` then primary `Create room` (or `Creating…` while pending); primary visually dominant, no duplicate submit above the fold. A compact status/error region sits above the footer, not in a toast-only channel. Validation is adjacent to its field with an announced error summary and focus on the first invalid control. Keep backend errors in the open dialog with all values intact. Sonner is for successful create/copy (and optional supplemental failure notice), **not** a substitute for inline validation or actionable mutation error. Successful creation closes the dialog only after the response succeeds; expose the returned invitation link in the existing safe success surface and allow copying. Never optimistically claim created or clear draft on request failure.

## Dialog geometry and interaction

- Use existing `src/components/ui/dialog` (shadcn Radix), scoped Craft warm paper/ink, SUIT/Pretendard, thin rules and **4px** bounded corners; profile avatar remains circular. At desktop use width `min(100% - 32px, 640px)` (a 600–640px cap acceptable after measuring), max-height `min(90dvh, 760px)`. Header and footer remain visible; form body has native vertical scroll with slim warm scrollbar and no clipped focus ring. No document horizontal overflow or scroll bleed. At 375/390px use 16–20px side clearance, max-height `calc(100dvh - 32px)` with safe-area/visual-viewport accommodation; stack date/time controls where needed, full-width 44px touch targets, never overlay a field behind the virtual keyboard. Verify at 375, 390, 768 and 1440, including a 320px-height/keyboard-reduced viewport. Do not impose body `overflow:hidden` beyond the Radix modal's lifecycle or animate height in a way that introduces a transient page scrollbar.
- On open, focus the title for an empty draft; for a restored draft focus the dialog heading or first meaningful field without selecting/replacing its contents. Escape, explicit Cancel, dialog close button and outside click dismiss the dialog **without resetting form state**. If the date range popover is open, its first Escape closes that popover and returns focus to its trigger; a subsequent Escape closes the dialog. Outside click on an inner picker only cancels its uncommitted selection; do not accidentally dismiss both layers. On dialog dismissal, restore focus to the invoking `New meeting`/guest CTA; reopening shows all last-entered fields, including title, name, range, times and timezone. While `Creating…`, disable duplicate submit and destructive dismissal; keep controls and content visible. `prefers-reduced-motion` eliminates dialog/picker transitions; normal entrance/exit is restrained opacity/6px and exiting content is inert, with no focus trap remaining on exit.
- Explicit reset is the sole discard path: a clearly labeled `Reset form` action (not confused with picker `Reset`) returns all fields to initial defaults after confirmation if nonempty, and clears tab-scoped stored draft. Closing never implicitly resets. After successful creation clear stored draft, reset form and close. On return from OAuth restore the filled dialog and require another explicit `Create room` press; do not auto-create or double-submit.

## Range, draft and login state machine

| Event/state | Required behavior |
|---|---|
| Home → open | Mount one dialog with current in-memory or restored draft; focus established as above. No mutation. |
| Date popover open | Select contiguous start/end within 14 **inclusive** days, keep open after first date, show selected endpoints/count, disable out-of-range end choices and support reverse-order restart. Use `Today` and a meaningful quick-range shortcut only if dates are consciously selected by the user. `Apply` commits selected complete range to the form; `Cancel` and outside/Escape keep the prior committed range; picker `Reset` clears only its working selection until Apply. Preserve month context and keyboard arrow/PageUp/PageDown/Enter support. Visible dates `yyyy.mm.dd` with zero padding, underlying ISO unchanged. |
| Dialog dismissal with edits | Preserve draft in component state **and** versioned, expiring, defensively parsed tab-scoped storage; persist before auth/navigation and preferably on edits or close so an accidental refresh does not destroy work. Never store credentials or invite tokens. Reopen without replacing fields. |
| Invalid Create | No OAuth, network creation or toast-only error; show field-level errors and focus first invalid field while dialog stays open. |
| Valid Create, authenticated | Submit once, show `Creating…`, disable duplicate action; success clears draft and closes to explicit invitation-link success state; error preserves form/dialog and offers retry. |
| Valid Create, guest | Save draft; close/unmount create Dialog **before** opening an accessible site-styled sign-in prompt (`Sign in with Google to create a room`, Cancel/Sign in). Never stack active dialogs or competing focus traps. Cancel returns to the filled create Dialog (or closed home with guaranteed obvious reopen and preserved values), with focus returned to Create; choose one consistent implementation and test it. |
| Google login error/cancel | Keep draft and give a visible retryable error; no silent discard. Returning-user sign-in also saves any existing draft before redirect. |
| OAuth callback | Restore validated internal destination and versioned unexpired draft; reopen *filled* creation Dialog, focus safely, show `Ready to create your room.` Do **not** automatically submit. Already-authenticated users skip the prompt. |

Keep `draft.mjs` version/expiry and `createIntent` semantics as source of truth; extend tests rather than making a second incompatible draft key. Avoid auto-opening on every mount once a user deliberately dismisses the restored dialog in the same tab. Authentication uncertainty is not guest state: wait for account resolution before showing the guest entry or deciding whether to prompt.
