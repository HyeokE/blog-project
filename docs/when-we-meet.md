# When We Meet — shared Supabase integration

Local routes: `/craft/when-we-meet` and `/craft/when-we-meet/[roomId]`. Domain/UI are isolated under `src/features/when-we-meet/`; the reusable public client is `src/lib/supabase/client.ts`. Environment names: `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. **Never use a service-role/secret key in browser variables.** The owner supplied these public values in ignored `.env.local`; this task did not inspect or overwrite them.

Room creation/joining cannot succeed until the owner reviews `supabase/migrations/20260929000000_wwm.sql` and applies it. This migration was **not applied** and no live create/save was verified. Do not change Auth without owner-managed provider setup; it can affect unrelated services sharing this project.

The draft creates only `wwm_` tables/functions plus a restricted `wwm_private` helper schema. Membership is created atomically with rooms; entry needs both an unguessable UUID room ID and independent invite UUID. Only authenticated members can read a room and its response rows. Each user can insert/update only their own response, subject to membership, composite FK, bounded aligned room-local slots and 14-day window. Private security-definer helpers bypass RLS solely for atomically joining/creating and membership checks; exposed `public.wwm_*` wrappers run as invoker and grant only authenticated execution. Review the SQL in a staging clone and test as anon, invited member, outsider and another member before applying to shared production. In particular audit function ownership, PostgREST schema exposure, `auth.uid()`, grants and room token leakage in logs/referrers.

Google sign-in runs on our own domain (2026-10-01): `GET /api/craft/auth/google?next=…` builds Google's authorization URL (code flow, PKCE S256, `nonce`=sha256(raw nonce) hex, HMAC-signed 10-minute state, `prompt=select_account`, scopes `openid email profile`) and keeps the verifier, raw nonce and safe `next` in an httpOnly SameSite=Lax cookie scoped to `/api/craft/auth/google/callback` (Secure on HTTPS). That callback verifies state/cookie/expiry, redeems the code with the client secret, and calls Supabase `signInWithIdToken` (raw nonce) on the writable server client, which sets the session cookies; Google tokens are never stored. It then 303s to `/craft/when-we-meet/auth/callback?next=…&signedIn=1` (or `&error=denied|expired|failed|unavailable`), a client page that only restores sessionStorage drafts/invites. One OAuth client (`GOOGLE_OAUTH_CLIENT_ID`/`_SECRET`, also configured as Supabase's Google provider so the ID-token audience matches) serves sign-in and Calendar; registered redirect origins are hyeok.dev, the Tailnet origin and http://localhost:3002 (`LOGIN_ORIGINS` in `src/lib/google-login.mjs`). Vercel previews show the `unavailable` error. Account read/signout use `/api/craft/auth`; list/room reads and mutations use `/api/craft/when-we-meet` under `auth.getUser()` and RLS, never a service-role key. Do not log/copy OAuth codes or tokens.

A complete invitation URL is a bearer invitation; any Google-signed-in user who possesses it can become a member and read participant names/availability. Rooms are not public searchable. Users should not post the link publicly. No OAuth calendar, notifications, payment, or fake local persistence. Google sign-in creates a browser-persisted user session; identity is owned by the Google-linked Supabase user. There is no anonymous fallback or fake local persistence.
